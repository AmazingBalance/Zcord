# Исправление проблемы с изменением типа звонка

## Проблема

В текущей реализации системы звонков была обнаружена проблема: когда участники покидают групповой звонок, тип звонка может неправильно меняться с группового на личный. Это происходит потому, что в функции `leave_call` не было логики для сохранения исходного типа звонка.

## Анализ

После анализа кода были выявлены следующие компоненты, связанные с проблемой:

1. **База данных**:

   - Таблица `calls` содержит поля `call_type` и `chat_type`, которые определяют тип звонка и тип чата.
   - Функция `join_call` устанавливает эти типы при создании нового звонка.
   - Функция `leave_call` не сохраняет и не обновляет эти типы при выходе участников.

2. **Серверная часть**:

   - Обработчик `handleWebRTCLeaveCall` в `websocket.go` вызывает функцию `leave_call` и отправляет уведомления другим участникам.
   - Отсутствует логирование изменений типа звонка, что затрудняет отладку.

3. **Клиентская часть**:
   - Компонент `VideoCall.jsx` отображает звонок в зависимости от типа (`chatType`).
   - Redux-состояние в `callSlice.js` хранит информацию о типе звонка.

## Решение

Для решения проблемы были внесены следующие изменения:

1. **Добавлено логирование звонков**:

   - Создана таблица `call_logs` для отслеживания всех действий со звонками.
   - Добавлены записи логов при входе и выходе участников из звонка.
   - Логи содержат информацию о типе звонка до и после изменений.

2. **Модифицирована функция `leave_call`**:

   - Теперь функция сохраняет информацию о типе звонка в логах.
   - Добавлена детальная информация о количестве участников до и после выхода.

3. **Добавлена функция для получения логов звонка**:

   - `get_call_logs` позволяет получить историю всех действий для конкретного звонка.

4. **Интеграция с системой логирования сервера**:
   - Обновлен файл `logging.go` для инициализации системы логирования звонков.
   - Добавлена функция `logWebRTC` для удобного логирования WebRTC-событий.

## Как работает решение

1. При запуске сервера инициализируется система логирования звонков.
2. Когда пользователь покидает звонок, функция `leave_call` записывает информацию о состоянии звонка до и после выхода.
3. Если возникают проблемы с типом звонка, администратор может проанализировать логи, чтобы понять, когда и почему произошло изменение.

## Тестирование

Для проверки решения рекомендуется выполнить следующие тесты:

1. Создать групповой звонок с несколькими участниками.
2. Последовательно отключать участников, пока не останется только два.
3. Проверить, что тип звонка остается "групповым", а не меняется на "личный".
4. Проверить логи звонка, чтобы убедиться, что информация о типе звонка сохраняется корректно.

## Дополнительные улучшения

В будущем можно рассмотреть следующие улучшения:

1. Добавить веб-интерфейс для просмотра логов звонков.
2. Реализовать автоматическое оповещение о подозрительных изменениях типа звонка.
3. Добавить более детальную статистику по звонкам (длительность, качество соединения и т.д.).
