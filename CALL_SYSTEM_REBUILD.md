# Перестройка системы видеозвонков

Этот документ описывает изменения, внесенные для перестройки системы видеозвонков в Zcord.

## Обзор

Система видеозвонков была полностью перестроена для решения нескольких проблем с предыдущей реализацией:

1. Двойное хранение информации о звонках (как в памяти, так и в базе данных)
2. Неоднозначные ссылки на столбцы в SQL-функциях
3. Ошибки тайм-аута при присоединении к существующим звонкам
4. Возможность зависания записей о звонках при возникновении ошибок

Новая реализация полагается исключительно на базу данных для управления состоянием звонков, с улучшенной обработкой ошибок и логикой повторных попыток на стороне клиента.

## Внесенные изменения

### 1. Изменения в базе данных

- Оптимизированные индексы для повышения производительности:

  - `idx_calls_chat_id_is_active` на `calls(chat_id, is_active)`
  - `idx_call_participants_call_id_is_active` на `call_participants(call_id, is_active)`

- Улучшенные функции базы данных:
  - `join_call`: Обрабатывает создание новых звонков или присоединение к существующим
  - `leave_call`: Обрабатывает выход из звонков и помечает их как неактивные, когда они пусты
  - `get_active_call`: Получает информацию об активном звонке с участниками
  - `cleanup_stuck_calls`: Новая функция для очистки зависших записей о звонках

### 2. Изменения на стороне сервера

- Удалены сессии звонков в памяти, чтобы полагаться исключительно на базу данных
- Улучшена обработка ошибок в обработчиках WebSocket
- Улучшено логирование для отладки проблем со звонками

### 3. Изменения на стороне клиента

- Улучшенный сервис WebRTC:

  - Лучшая обработка ошибок и логика повторных попыток
  - Экспоненциальная задержка для повторных попыток
  - Правильная очистка медиа-потоков
  - Уникальные идентификаторы запросов для отслеживания

- Улучшенное хранилище Redux:
  - Добавлено отслеживание ошибок и механизмы восстановления
  - Добавлено отслеживание количества повторных попыток
  - Улучшенное управление состоянием звонка

## Как применить изменения

1. **Очистить существующие звонки**:

   ```bash
   podman exec zcord-postgres-temp psql -U zcord -d zcord -f /tmp/clean_all_calls.sql
   ```

2. **Применить изменения в базе данных**:

   ```bash
   bash rebuild_call_system.sh
   ```

3. **Перезапустить сервер**:
   Сервер необходимо перезапустить, чтобы изменения вступили в силу.

## Тестирование новой реализации

Чтобы протестировать новую систему звонков:

1. Откройте приложение в двух разных браузерах или вкладках браузера
2. Войдите с двумя разными учетными записями
3. Перейдите в один и тот же чат в обоих браузерах
4. Инициируйте звонок из одного браузера
5. Присоединитесь к звонку из другого браузера
6. Убедитесь, что аудио и видео работают правильно
7. Покиньте звонок из обоих браузеров
8. Убедитесь, что звонок правильно завершен

## Устранение неполадок

Если вы столкнулись с проблемами с новой системой звонков:

1. Проверьте логи сервера на наличие ошибок
2. Убедитесь, что функции базы данных правильно установлены
3. Убедитесь, что все активные звонки очищены
4. Перезапустите сервер и клиент

Если проблемы не устраняются, вы можете снова запустить скрипт очистки:

```bash
podman exec zcord-postgres-temp psql -U zcord -d zcord -f /tmp/clean_all_calls.sql
```

## План отката

В случае критических проблем с новой реализацией:

1. Восстановите схему и функции базы данных из резервной копии
2. Восстановите код клиента и сервера из резервной копии
3. Запустите скрипт очистки, чтобы пометить все активные звонки как неактивные
4. Перезапустите сервер
