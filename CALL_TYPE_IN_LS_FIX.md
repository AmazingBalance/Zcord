# Исправление проблемы с типом звонка в личных чатах

## Проблема

В приложении Zcord была обнаружена проблема: в личных чатах (LS) инициализируется групповой звонок вместо личного. Это происходит из-за того, что функция `get_active_call` возвращает тип звонка и тип чата из таблицы `calls`, но не проверяет, соответствует ли тип чата в таблице `calls` реальному типу чата.

Когда пользователь присоединяется к существующему звонку, клиентский код использует тип чата, полученный от сервера, для определения интерфейса звонка. Если тип чата неверный, то интерфейс звонка будет отображаться некорректно.

## Анализ

После анализа кода были выявлены следующие компоненты, связанные с проблемой:

1. **База данных**:

   - Функция `get_active_call` возвращает тип звонка и тип чата из таблицы `calls`.
   - Тип чата в таблице `calls` устанавливается при создании звонка и не обновляется при изменении количества участников.

2. **Клиентская часть**:
   - Компонент `ChatZone.jsx` при присоединении к существующему звонку использует тип чата, полученный от сервера.
   - Компонент `VideoCall.jsx` отображает интерфейс звонка в зависимости от типа чата.

## Решение

Для решения проблемы были внесены следующие изменения:

1. **Модификация функции `get_active_call`**:

   - Теперь функция определяет реальный тип чата на основе данных из таблицы `chats`.
   - Возвращает правильный тип чата вместо значения из таблицы `calls`.

2. **Добавление логирования**:
   - Создан триггер для логирования вызовов функции `get_active_call`.
   - Логи содержат информацию о типе чата до и после изменения.

## Как работает решение

1. Когда клиент запрашивает информацию об активном звонке, функция `get_active_call` определяет реальный тип чата на основе данных из таблицы `chats`.
2. Функция возвращает правильный тип чата вместо значения из таблицы `calls`.
3. Клиентский код использует правильный тип чата для определения интерфейса звонка.

## Тестирование

Для проверки решения рекомендуется выполнить следующие тесты:

1. Создать личный чат между двумя пользователями.
2. Инициировать звонок в этом чате.
3. Проверить, что тип звонка отображается как "Личный звонок", а не "Групповой звонок".
4. Проверить логи звонка, чтобы убедиться, что тип чата определен правильно.

## Дополнительные улучшения

В будущем можно рассмотреть следующие улучшения:

1. Обновлять тип звонка в таблице `calls` при изменении количества участников.
2. Добавить проверку типа чата на клиенте перед отображением интерфейса звонка.
3. Добавить автоматические тесты для проверки корректности типа звонка в разных типах чатов.
